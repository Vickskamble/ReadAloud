# READALOUD — VOICE PRONUNCIATION IMPROVEMENT

## Complete Development Prompt

You are working on the existing **ReadAloud** application.

Your task is to improve the **voice pronunciation and text-to-speech reading system**.

The app's purpose is simple:

> User pastes any message/text → app reads it aloud with the most natural pronunciation possible.

Supported text can contain:

* English
* Hindi
* Hinglish
* Hindi + English mixed text
* Numbers
* Dates
* Time
* Currency
* Abbreviations
* Names
* Technical words
* URLs
* Email addresses
* Emojis
* Punctuation

---

# 1. IMPORTANT PRODUCT RULES

## DO NOT use AI

This pronunciation system must NOT use:

* OpenAI
* Gemini
* Claude
* ChatGPT API
* Any generative AI API
* Any external AI pronunciation API
* Any cloud-based AI language detection

Use only:

* Local text processing
* Unicode/script detection
* Local dictionaries
* Rule-based pronunciation processing
* Native/device Text-to-Speech
* Offline/local resources wherever available

---

# 2. PRIVACY

The user's pasted text is private.

NEVER:

* Upload text to a server
* Store the actual message permanently
* Send text to analytics
* Send text to crash reporting
* Send text to Firebase logs
* Send text to external APIs
* Store text in a database

Text should exist only during the active reading session.

When the user clears the text or the session ends, temporary text data should be removed.

# 5. SCRIPT DETECTION

Detect whether the text contains:

### Devanagari / Hindi

Example:

आज मुझे ऑफिस जाना है।

Use Hindi TTS where available.

### English

Example:

I am going to the office.

Use English TTS.

### Roman Hindi / Hinglish

Example:

Aaj mujhe office jaana hai.

Detect this as mixed/roman Hindi instead of assuming that every Roman-script word is English.

### Mixed Language

Example:

Aaj meeting 5 PM par hai.

Detect individual language segments.

---

# 6. TOKEN CLASSIFICATION

Each token should be classified locally as one of:

* HINDI_DEVANAGARI
* HINDI_ROMAN
* ENGLISH
* NUMBER
* DATE
* TIME
* CURRENCY
* EMAIL
* URL
* ACRONYM
* EMOJI
* PUNCTUATION
* PROPER_NAME
* TECHNICAL_WORD
* UNKNOWN

The classifier must be deterministic and local.

---

# 7. HINGLISH SUPPORT — MOST IMPORTANT

The app must specifically handle Roman Hindi/Hinglish.

Examples:

Aaj mujhe office jaana hai.

Mujhe report send kar dena.

Kal meeting hai.

Aap mujhe message kar dena.

Tum kahan ja rahe ho?

Mujhe ye file download karni hai.

The system must NOT simply send the entire sentence to an English TTS engine.

It should identify Hindi-origin Roman words and English words.

Example:

"Aaj mujhe office jaana hai."

Internally:

Aaj → HINDI_ROMAN

mujhe → HINDI_ROMAN

office → ENGLISH

jaana → HINDI_ROMAN

hai → HINDI_ROMAN

# 11. IMPORTANT LANGUAGE SEGMENTATION RULE

Do NOT switch TTS language for every individual word.

That will create robotic speech.

Example:

Aaj mujhe office jaana hai.

Do NOT create:

Aaj → Hindi TTS

mujhe → Hindi TTS

office → English TTS

jaana → Hindi TTS

hai → Hindi TTS

Instead group consecutive compatible words.

Possible structure:

Segment 1:
Aaj mujhe

Segment 2:
office

Segment 3:
jaana hai

Then process these segments sequentially.

The segmentation algorithm should minimize unnecessary language switching.

---

Create a sequential speech queue.

Example:

↓
Segment 3
↓

The next segment must start only after the previous segment finishes.

Never allow multiple TTS calls to overlap.

# 22. EMAIL

Example:

Normalize:

# 23. URL

Example:

Do not unnecessarily read every URL character.

Convert the URL into a readable spoken form.

For example:

should not be spoken unless required.

Prefer meaningful domain pronunciation.

5. Native TTS fallback

# 30. PRONUNCIATION PRIORITY

Use this priority order:

2. Proper-name/technical pronunciation dictionary

6. Contextual classification
7. Rule-based pronunciation
8. Native TTS fallback

---

# 37. DO NOT CLAIM 100% PRONUNCIATION ACCURACY

This is a rule-based offline pronunciation system.

It should be designed for continuous improvement.

When a pronunciation problem is found:

1. Identify the word.
2. Identify why it was classified incorrectly.
3. Fix the relevant rule/dictionary.
4. Add a regression test.
5. Re-test existing cases.

Do not fix one word by breaking other words.
