# ReadAloud — Text-to-Speech Reading App

## Complete Product & Development Specification

### 1. Project Overview

Build a lightweight **Text-to-Speech (TTS) application** called **ReadAloud**.

The core purpose of the application is extremely simple:

> **User koi bhi text paste/type kare → app us text ko loudly read kare.**

The text can be:

* English
* Hindi
* Hinglish
* Marathi
* Gujarati
* Bengali
* Tamil
* Telugu
* Any other language supported by the device/browser TTS engine

### Core Principle

**NO AI should be used.**

The application must use the **native/device/browser Text-to-Speech engine**.

There should be:

* No AI API
* No OpenAI API
* No Gemini API
* No Claude API
* No cloud-based AI processing
* No backend database
* No user account
* No login
* No text storage

---

# 2. Main User Flow

The application should have an extremely simple workflow:

```text
Open App
   ↓
Paste / Type Text
   ↓
Select Language / Voice (optional)
   ↓
Press PLAY
   ↓
Text is spoken loudly
   ↓
User can Pause / Resume / Stop
   ↓
User can clear text
```

The app should feel like a **simple utility**, not a complicated productivity application.

---

# 3. Privacy Requirement

Privacy is one of the most important product requirements.

### Text must NOT be stored.

The application must not permanently save:

* User text
* Reading history
* Previous text
* User documents
* Voice history
* Usage history

### No database

Do NOT implement:

* Firebase
* Supabase
* MongoDB
* MySQL
* PostgreSQL
* Local database

unless specifically required later.

### Temporary memory

Text may exist temporarily in the application memory while the user is using the app.

Example:

```text
User opens app
↓
Pastes text
↓
Text remains temporarily in memory
↓
Text is spoken
↓
User closes/refreshes app
↓
Text is cleared
```

### Important

Do not implement:

* "Recent texts"
* "History"
* "Saved texts"
* "Favorites"
* "Documents"
* "Cloud sync"

---

# 4. No AI Requirement

This application must NOT use artificial intelligence.

Do not add AI-based:

* Translation
* Summarization
* Grammar correction
* Text rewriting
* Text understanding
* AI voice generation
* AI pronunciation
* AI chatbot

The application is strictly:

> **Text → Native TTS Engine → Audio**

---

# 5. TTS Engine

Use the native Text-to-Speech capability available on the target platform.

For web:

```javascript
window.speechSynthesis
SpeechSynthesisUtterance
```

For Android/native implementation, use the platform's native TTS engine.

The implementation should detect available voices from the user's device.

---

# 6. Language Support

The application should support all voices exposed by the device/browser.

Do NOT hardcode only English.

Example available languages may include:

```text
English
Hindi
Marathi
Gujarati
Bengali
Tamil
Telugu
Kannada
Malayalam
Punjabi
Urdu
etc.
```

Actual available languages depend on the device/browser and installed TTS voices.

Therefore:

### Voice detection

On application startup:

```text
Load available voices
↓
Read language + voice information
↓
Populate Voice/Language selector
```

If a voice is not installed on the user's device, the application should not pretend that it is available.

---

# 7. Hinglish Support

Hinglish requires special consideration.

Example:

```text
Hello bhai, kya haal hai?
Aaj office jaana hai.
```

There may not always be a dedicated Hinglish voice.

Therefore, the app should provide a simple language/voice selection mechanism.

The user can choose the voice that produces the best pronunciation on their device.

Do NOT use AI to detect or convert Hinglish.

# 12. Automatic Text Chunking

This is an important technical requirement.

Native browser/device TTS engines may have limitations when extremely large text is sent as one utterance.

Therefore:

### Do NOT blindly send huge text as one TTS request.

Implement text chunking.

Example:

```text
Large text
↓
Split into manageable chunks
↓
Speak Chunk 1
↓
Speak Chunk 2
↓
Speak Chunk 3
↓
Continue until complete
```

Chunking should preferably respect:

* Sentences
* Paragraphs
* Word boundaries

Do not cut words in half.

---

# 13. Long Text Handling

The application should support reasonably long text.

Examples:

* WhatsApp messages
* Emails
* Articles
* Notes
* PDFs copied as text
* Web content copied as text
* Study material

If the user pastes very large text:

```text
Detect large input
↓
Chunk text
↓
Queue chunks
↓
Read sequentially
```

Do not crash or freeze the application.

---

# 14. Empty Text Handling

If the user presses Play without entering text:

Show a simple message:

```text
Please enter some text first.
```

Do not start the TTS engine.

---

# 15. Clear Button

When user presses:

```text
CLEAR
```

the application should:

1. Stop speech
2. Clear speech queue
3. Clear text field
4. Reset playback state

No text should remain in application state unnecessarily.

---

# 16. Stop Behaviour

When user presses STOP:

```text
Stop current speech
↓
Cancel remaining queue
↓
Reset playback state
```

The next Play should start from the beginning of the current text.

---

# 17. Pause / Resume

If supported by the platform:

```text
PLAY
↓
PAUSE
↓
RESUME
```

The application should preserve the current playback position as far as the native TTS engine permits.

If exact pause/resume position cannot reliably be controlled by the target platform, use the platform's native pause/resume functionality rather than creating a fake implementation.

---

# 18. Auto Continue

When one speech chunk finishes:

```text
Chunk 1 finished
↓
Automatically speak Chunk 2
↓
Chunk 2 finished
↓
Automatically speak Chunk 3
```

The user should not need to manually press Play after every chunk.

---

# 19. Error Handling

Handle common TTS errors gracefully.

Examples:

```text
TTS unavailable
Voice unavailable
Speech failed
Browser does not support TTS
```

Display a simple understandable message.

Example:

```text
Text-to-Speech is not available on this device/browser.
Please try another browser or install a supported voice.
```

Do not expose technical stack traces to the user.

---

# 20. Offline Requirement

Where the device/browser's native TTS engine works offline, the application should work without an internet connection.

The app itself must NOT depend on an external AI/cloud speech API.

Important distinction:

```text
Application Internet Requirement:
NO

Device TTS availability:
Depends on OS/browser/installed voices
```

# 36. Text Chunker Responsibilities

The text chunker should:

1. Receive complete text
2. Detect paragraphs/sentences
3. Create manageable chunks
4. Avoid breaking words
5. Return chunks in correct order

Example:

```text
Input:
"Hello. This is a long paragraph..."

Output:
[
  "Hello.",
  "This is a long paragraph..."
]
```

For extremely long sentences, split safely at word boundaries.

---

# 37. Voice Detection

Use:

```javascript
speechSynthesis.getVoices()
```

and:

```javascript
speechSynthesis.onvoiceschanged
```

because some browsers populate voices asynchronously.

The application must handle this correctly.
